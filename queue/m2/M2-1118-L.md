M2-1118-L — Mac CI 대기열 줄이기: ci 잡 단계별 소요 측정 → 돈 안 드는 단축 적용

원장 대사: M2-1118-K 리포트(대기 10건 · ci 최대 40분 · 실행기 1대) · Kyu 11-18 "절감은 무조건" · decision CI(#360: 전 잡 self-hosted · draft=가벼운 잡)

## 목적 (쉬운 말)
검사(CI)를 Mac 한 대가 줄 세워 처리하는데 한 건에 최대 40분이 걸려 10건이 밀려 있다. 그래서 리뷰 승인까지 끝난 PR 3개가 몇 시간째 머지를 못 한다. 돈을 더 쓰지 않고, ① 어디서 시간이 새는지 재고 ② 30초짜리 가벼운 검사가 40분짜리 무거운 검사 뒤에 줄 서지 않게 하고 ③ 같은 일을 반복하지 않게 해서 대기열을 줄인다.

## 범위
- storeport-wts/hub-m2 · 브랜치 `ci/M2-1118-L-queue` · PR · /loop 금지 · **45분 상한** · model=sonnet
- 건드릴 파일: `.github/workflows/*.yml` 만. 테스트 코드·앱 코드 금지.

## [REQ]
1. 측정: 최근 완료된 `ci` run 3개의 **단계(step)별 소요**(`gh run view <id> --log` 또는 `--json jobs`) — 의존성 설치 · 빌드 · unit · pos-integration · e2e 중 무엇이 길고, 큐 대기 시간과 실제 실행 시간을 분리.
2. 가벼운 잡(changes-filter · markers-and-forbidden · feature-map-check · ci-summary · stale-deferred)이 무거운 잡 뒤에 줄 서지 않도록: 라벨 `curiocity-mac-light` 로 보내는 안(= Kyu 가 같은 Mac 에 가벼운 전용 실행기 1대 더 등록 필요)을 기본으로 workflow 에 반영하되, **그 라벨 실행기가 없으면 기존 `curiocity-mac` 으로 돌도록** 깨지지 않게(불가하면 PR 본문에 등록 전후 머지 순서 명시).
3. 반복 제거: self-hosted 라 pnpm store 는 이미 로컬에 있으니 `pnpm install --frozen-lockfile --prefer-offline` 확인 · 빌드 산출물을 같은 run 의 뒤 잡들이 재사용(artifact 대신 같은 실행기 작업 폴더/캐시) · 변경 없는 앱(customer-display 등)은 paths 로 건너뛰기 · main 에서 ci-summary 가 27분 걸리는 이유(다른 잡 기다림?) 수정.
4. 적용 전후 예상 1건당 시간 표 · PR 본문에 선택지·채택·이유.
