## 확정 (Kyu · 세법 근거 = 자카르타 Bapenda PBJT 안내: 루피아 바우처 결제분도 과세표준 포함 · PP 35/2023 Ps.19(2))
1. **적립금 = 결제수단(tender 성격)** · 선할인 아님. PB1(PBJT)은 **원래 총액**에 부과 → 적립금은 총액(grand_total) 결제에 사용. 예: 100,000 + PB1 10,000 = 110,000 → 적립금 20,000 → 손님 90,000 / 전액 사용 → 손님 0 · 매장은 PB1 10,000 그대로 신고.
2. 전액·부분 사용 모두 가능 · `max_use_pct_per_order` 기본 100.
3. **Admin 신규 키 `tax_mode`**: `"payment"`(기본 · 세법 기준) | `"discount"`(세무사 확인 후 전환용 · 선택 시 Admin 경고 문구). 
4. **적립 대상 = 실제로 낸 돈**(적립금 사용분 제외) · `earn_base` 기본을 `"paid_non_credit"`(적립금 외 실제 결제액 · 세금 포함) 으로 변경 · 옵션 `"paid_non_credit_pre_tax"`(세전 비례). 예: 90,000 × 적립률.
5. **나눠결제 2-tender 한도와 별도**: 적립금은 한도에 세지 않음(적립금 + 현금 + QRIS 가능) · tenders 카운트 SoT 와의 관계 명시.
6. 영수증 줄 순서: Subtotal → PB1 → Total → Store credit −X → Cash/QRIS(잔액) → Credit earned +Y → Credit balance Z.
7. 환불: 적립금으로 낸 몫은 적립금으로 복원(원 결제수단 원칙 · S3 순서에서 적립금 위치 제안) · 적립분 회수 안분.
