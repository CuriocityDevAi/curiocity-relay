모든 새 주문에 사람이 읽는 긴 번호를 붙인다. 형식 `{매장닉네임}{YY}{월}{일련}`.
- 월 1자리: 1~9, **A=10월 B=11월 C=12월** · YY = 연도 뒷 2자리 · 월 경계 = Asia/Jakarta(WIB) 자정
- 일련: (매장, 연월)마다 **시작번호부터 1씩 증가**. 시작번호 기본 1000. 4자리 0 채움, 9999 초과 시 5자리로 늘어남(오류 아님). 예: PIM 2026년 11월 첫 주문 = `PIM26B1000`, 다음 `PIM26B1001`.
- 동시 주문에도 중복·건너뛰기 없이: DB 원자적 카운터(예: (store, yyyymm) 행 upsert + 증가를 한 문장으로 · 행 잠금). 취소된 주문도 번호 유지.
- 저장 위치: 기존 `display_id`(자동 증가)는 건드리지 말고 내부용으로 유지. **Medusa 2.12+ 의 `custom_display_id` + order 모듈 옵션 `generateCustomDisplayId`** 를 우선 사용.

**0단계(필수 · 먼저 커밋)**: storeport 의 @medusajs 버전 확인. 2.12 미만이면 **코딩 중단** → 리포트에 ⓐ 업그레이드 범위·위험 ⓑ 우회안(자체 컬럼/링크 + 주문 생성 훅) 비교표만 쓰고 종료. 코어에 있는 기능은 새로 만들지 않는다("코어에 있음 / 우회 / 신규" 대사표를 PR 본문에).

**매장은 무엇인가**: POS 주문이 어느 매장 것인지 지금 코드에서 쓰는 기준(레지스터의 stock location / sales channel 등)을 따른다. 채택 기준을 PR 에 3줄로. POS 가 아닌 주문(온라인·Admin 수동)도 같은 규칙을 타되, 매장을 특정 못 하면 아래 '닉네임 없음' 규칙.

**Admin 화면**(기존 Admin POS Settings 계열 · 사이드바 공식 route 방식 — #213 PIN 페이지 참고):
- 매장별 **닉네임**: 영문 대문자 2~4자 · 매장끼리 중복 금지 · 그 매장에 번호가 한 번이라도 발급되면 잠금(화면에 잠금 이유 표시).
- **매달 시작번호**: 정수 1~9999 · 기본 1000 · 변경은 **다음 달부터 적용**(화면에 "Applies from <다음 달>" 표시 · 이번 달 번호 충돌 방지).
- 미리보기: "Next order number: PIM26B1003".
- UI 영어 · 색 하드코딩 금지.

**닉네임 없음**: 주문 생성을 실패시키지 않는다. custom_display_id 비움 → 화면은 기존 display_id 로 fallback · 경고 로그 · Admin 설정 화면 상단에 "Set a nickname for <매장>" 배너.
**기존 주문 백필 없음.**
**노출**: POS 앱이 쓰는 주문 조회·목록·영수증 데이터 API 응답에 `custom_display_id` 포함 · Admin Orders 목록에 컬럼 표시(View Configurations 등 코어 방식 우선) · Admin 주문 검색이 이 번호로도 되면 좋음(코어가 지원하면). POS 앱 화면 변경은 이 라운드 범위 밖(fork 라운드에서).
