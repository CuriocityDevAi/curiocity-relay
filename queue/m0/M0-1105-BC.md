[REQ]
1. **env**: `XENDIT_API_KEY` 우선, 없으면 `XENDIT_SECRET_KEY` 읽기. `XENDIT_WEBHOOK_TOKEN`. 매장 설정(pos_settings.xendit) 값이 있으면 그것 우선 — 저장 구조·읽기 함수만(Admin UI 는 M1 다음 라운드). 키 없으면 QRIS 요청은 명확한 400 `xendit_not_configured`.
2. **QR 생성**: POST /v3/payment_requests (channel QRIS · amount = 남은 금액 · 15분 만료 · reference_id = `<orderId>:<tenderSeq>:<nonce>`). 앱에 돌려줄 것 = qr_string · expires_at · payment_request_id 만(키·raw 응답 저장 금지). 기존 tender 기록 모델에 pending QRIS tender.
3. **webhook**: Medusa v2 의 실제 payment webhook 경로를 확인해 쓸 것(계획서의 `/hooks/payment/xendit` 가 Medusa 규칙 `/hooks/payment/{provider_id}` 과 맞는지 — 예: `xendit_xendit`). x-callback-token 검증(불일치 401). paid → tender captured·주문 Paid(현금 경로와 같은 완료 처리 재사용) · expired → tender expired. **멱등**(같은 이벤트 2번 = 1번 처리) · 금액 불일치 거부+로그.
4. **상태 조회**: 앱 폴링/"Check payment" 용 GET — 우리 DB 상태 + (pending 이면) Xendit 조회로 보정.
5. **재생성**: 만료된 QR 에 대해 캐셔가 "다시" → 새 payment_request(이전 것 expired 처리). 자동 재발행 없음.
6. **테스트**(fixture 기반): 생성 · webhook paid → Paid · 중복 webhook · 토큰 불일치 401 · 만료 · 금액 불일치 · 키 없음 400. CI pos-integration 에 편입 — **push 후 새 CI run 으로 판정**.
7. 환불·취소(J-d)는 이번 범위 밖.
