# Kyu 결정 — P6 환불 · 보이드 · 분할 결제 (11-10 15:43 WIB)

근거: m1/M1-1105-AF-report.md (계획서 §5 Q1~Q5). 마감 때 open-requirements.md "Kyu 결정 정본"에 합침.

## Kyu 원문
- "질문들(Q1~5)에 대해서 대답할게. 전부 권장안에 따름."
- "원거래가 CARD 이면, CARD 단말기를 통한 VOID/REFUND 가 성공해야 POS 에서 취소 처리. (이것은 매니저 PIN 필요없음) 그런데 카드 단말기에서 정상적으로 VOID/REFUND 처리가 안될 경우를 대비해서 CASH 로 처리 가능한 옵션을 둠. (이것은 매니저 PIN 필요) 원거래가 CASH 이거나, QRIS 이면 현금으로 고객에게 지불해야 하거든. (이것도 매니저 PIN 필요)"
- "매니저 PIN 은 MEROS ADMIN 화면에서 확인 가능하고, 4자리이면서, 하루에 한 번씩 변하도록 하자."

## 확정 표
| 항목 | 결정 |
|---|---|
| Q1 보이드 범위 | 같은 교대(shift) 안이면 언제든 · 교대 넘으면 환불 |
| Q2 환불 권한 | 매니저 PIN — 단 **원거래 CARD + 단말기 VOID/REFUND 성공** 경로는 PIN 불필요 |
| Q3 현금 환불 | 서랍 열림 + Cash Movement(−금액) 자동 기록 |
| Q4 분할 결제 | 최대 2개 tender |
| Q5 부분 환불 | 품목(수량) 단위 |
| 환불 수단 | CARD 원거래 → ① 단말기 VOID/REFUND(PIN 없음) ② 단말기 실패 시 CASH(PIN) · CASH/QRIS 원거래 → CASH(PIN) |
| 매니저 PIN | 4자리 · 하루 1회 변경 · MEROS Admin 에서 확인 |

## 오케 기술 해석 (Kyu 확인 불필요 · 다르면 정정)
- EDC 는 수동 연동 → "단말기 VOID/REFUND 성공" = 캐셔가 단말기에서 처리하고 **단말기 승인번호(6자리)** 를 POS 에 입력 → 서버 기록(입력 없으면 진행 불가).
- 일일 PIN = 서버 비밀값 + 매장 id + WIB 날짜로 계산(DB 저장 없음) · WIB 자정 교체 · 오입력 5회 → 15분 잠금 · 성공/실패 감사 기록(누가·언제·주문).

- 서버 2차: 품목 단위 반품·재고 복귀 · 분할 결제(2 tender).
