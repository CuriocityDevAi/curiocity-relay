## 확정 레이아웃 (Kyu 11:01 개정 반영 — 10:47·10:56 판 대체)
공통 규칙 (허브 큐 · CI 큐 동일): **같은 줄 오른쪽 칩 = 대기 중** (줄 선 순서 · 대기 분) · **아랫줄 └ = 실행 중** (스피너가 돌며 경과 분). 실행 중이 없으면 └ 줄 없음. 대기도 실행도 없으면 `—`.
움직임: 실행 중 └ 줄 앞에 스피너(⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏ · 약 120ms 프레임 · 데이터 갱신 주기와 별개로 화면만 돌림 · 선택/스크롤 안 깨짐).

구역 순서 (위→아래):
1. **상단 요약 줄**: ●진행 N · ■주의 N · ✔오늘 N · 러너 v · CI 러너 4대 상태(OFF 빨강) · 갱신 시각.
2. **주의**(■/▲) — 어느 단계든 노·빨이면 여기로 올림 + 다음 줄에 이유.
3. **허브 큐** — 제목 `─ 허브 큐 (m0 2 · m1 0 · …) ─` = 허브별 대기 건수. 허브마다: 오른쪽 칩 = claim 없는 queue/ 프롬프트, 아랫줄 └ = started claim 인 프롬프트.
4. **CI 큐** — 제목 `─ CI 큐 (SH 2 · SL 1 · FH 2 · FL 1) ─` (SH=storeport-heavy · SL=storeport-light · FH=fork-heavy · FL=fork-light · 숫자 = 풀별 대기 건수 · 클라우드 넘김이 있을 때만 `· CL n` 추가). 러너 풀별 줄: 오른쪽 칩 = queued 잡, 아랫줄 └ = in_progress 잡. 칩은 프롬프트 ID(PR→ID 매핑, 없으면 #PR) + 분. 러너 OFF 면 줄 빨강 + 이유.
5. **진행 중** — 단계 띠 **9단계**: 큐 · 작업 · 리포트 · PR · CI대기 · CI실행 · CI결과 · 리뷰 · 머지.
6. **오늘 완료 N** (접힘 · Enter 펼침).
7. 하단 키: j/k 이동 · Enter 상세 · / 필터 · r 새로고침 · q 종료.
